# AgenticPythonScripts

A small collection of Python automation scripts. The first tool in this repository is a
SQL Server database structure exporter for documentation, analysis, and AI-assisted database
work.

## SQL Server database structure exporter

[`export_sql_database_structure.py`](./export_sql_database_structure.py) connects to a SQL Server
database and exports its **structure and metadata**. It is intended to help database
administrators and developers document a schema, inspect relationships, and prepare a structured
knowledge source for tools such as Microsoft Copilot.

The exporter does **not** read or export table row data. It generates a timestamped export
directory and ZIP archives containing:

- CSV catalogues for schemas, objects, columns, keys, foreign keys, indexes, constraints,
  parameters, dependencies, triggers, synonyms, and other database metadata.
- Individual SQL files for supported tables, views, procedures, functions, triggers, synonyms,
  and sequences, where definitions are available.
- A combined schema SQL file, database information, an object status index, and a JSON manifest.
- Optionally, a `CopilotKnowledge` directory with per-object Markdown, metadata, a database
  overview, agent guidance, and a register of unavailable definitions.

### Important: scope and limitations

This tool is for **schema documentation**, not database backup or migration. It does not export
table data, server-level objects, SQL Agent jobs, credentials, or secrets. Encrypted modules and
objects hidden by the connecting account's metadata permissions may not have definitions.

Table DDL is assembled from SQL Server catalog metadata, not generated by SMO. Review it before
using it to recreate a database: advanced table/storage features and some specialized indexes,
partitioning, XML schemas, or user-defined types may need additional scripting. See
`ScriptedObjectIndex.csv` for per-object status and notes.

SQL module source can contain internal server names, file paths, URLs, email addresses, comments,
or hard-coded literals. Inspect exported files before sharing them. Approximate row counts, when
requested, come from partition metadata; they are not live `COUNT(*)` results.

## Requirements

- Python 3.10 or later
- Microsoft's [`mssql-python`](https://pypi.org/project/mssql-python/) Python driver
- Network access to SQL Server
- A SQL login or Windows account allowed to connect and view database metadata

The driver package supplies its SQL Server connectivity components; a separately installed
system ODBC driver is not required.

## Installation on Windows

Open PowerShell in the repository directory:

```powershell
cd C:\path\to\AgenticPythonScripts
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r .\requirements.txt
```

If PowerShell blocks virtual-environment activation, you can either allow it for the current
PowerShell process and retry activation:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Or use the virtual environment's Python directly without activating it:

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

## Run the exporter

### Windows integrated authentication

Use the SQL Server name/instance, database name, and a directory where the export files should be
created:

```powershell
python .\export_sql_database_structure.py `
    --server "sqlserver.example.com" `
    --database "MyDatabase" `
    --output "C:\Temp\DatabaseSchema"
```

For a named instance or a server listening on a specific TCP port, use the connection format
configured for that SQL Server, for example `"sqlserver.example.com\INSTANCE"` or
`"sqlserver.example.com,1433"`.

### SQL authentication

Pass the SQL login name. The exporter prompts for the password without displaying it:

```powershell
python .\export_sql_database_structure.py `
    --server "sqlserver.example.com,1433" `
    --database "MyDatabase" `
    --output "C:\Temp\DatabaseSchema" `
    --username "sql_user"
```

Do not put passwords directly in command history or commit them to source control.

### Optional arguments

| Argument | Purpose |
|---|---|
| `--encrypt` | Enable encryption for the SQL Server connection. |
| `--trust-server-certificate` | Skip server certificate validation. Use only when appropriate for your environment. |
| `--include-system-objects` | Include Microsoft-shipped objects where supported. |
| `--include-permissions` | Include the database permissions catalogue. |
| `--include-row-counts` | Include approximate table row counts from partition metadata. |
| `--skip-copilot-knowledge` | Do not create the Copilot-ready directory or its transfer ZIP. |
| `--overwrite` | Replace output files if the generated timestamped export path already exists. |
| `--help` | Show all command-line options. |

## Understand the output

The `--output` value is a **parent directory**. Each run creates a timestamped subdirectory named
after the database and a technical ZIP archive beside it. Unless
`--skip-copilot-knowledge` is set, the export also includes a `CopilotKnowledge` subdirectory and
a separate `_CopilotKnowledge.zip` archive.

Important files include:

- `Metadata\*.csv`: queryable catalogues of database structure and relationships.
- `ScriptedObjectIndex.csv`: every handled object, its export status, paths, and notes.
- `CombinedSchema.sql`: combined DDL for convenient inspection (individual scripts and status
  notes should be checked before reuse).
- `DatabaseInfo.json` and `Manifest.json`: database details, export options, counts, and warnings.
- `CopilotKnowledge\`: object-level Markdown and copied metadata organized for knowledge ingestion.

For a SharePoint knowledge source, upload the **contents** of the `CopilotKnowledge` folder and
preserve its folder hierarchy. Review the generated content before making it available to other
people.

## Troubleshooting

- **`ModuleNotFoundError: mssql_python`**: activate `.venv` and run
  `python -m pip install -r .\requirements.txt`.
- **Connection/login errors**: confirm the server/instance and database names, network access,
  authentication method, and that the account can view database metadata.
- **TLS/certificate errors**: use `--encrypt` when required by policy. Do not use
  `--trust-server-certificate` unless your environment explicitly allows bypassing certificate
  validation.
- **Objects missing or definitions unavailable**: metadata visibility is permission-dependent;
  encrypted modules do not reveal their source definitions.
- **DDL needs review**: check `ScriptedObjectIndex.csv` notes and the limitations above. This
  exporter does not promise a complete, production-ready database recreation script.
